# Pex Android shell (templates)

Kotlin/Jetpack Compose templates for the Pex Android target — the Android
analogue of `src-tauri/ios/Pex/`. These are **heavily-commented design
documents with placeholder UI**, not a buildable app on their own. The real,
buildable project is generated by `tauri android init` (which needs the Android
SDK + NDK); you then copy these files into it.

```
Pex/
├── MainActivity.kt   # ComponentActivity entry, Compose two-tab bottom nav (API 24+)
├── PRsTab.kt         # Single persistent WebView for the review workflow
├── SettingsTab.kt    # Settings tab (shared webview, tab-communication notes)
└── WebView.kt        # AndroidView WebView wrapper + full wry/Tauri setup checklist
```

## What's already done (shared, no toolchain needed)

- **Frontend** — `src/lib/platform.ts` `isMobile()` is generic (touch + narrow
  viewport), so `MobileShell`, the responsive CSS, touch diff selection, and
  `visualViewport` keyboard avoidance already work on Android phones.
- **Rust backend** — `#[cfg_attr(mobile, tauri::mobile_entry_point)]` and the
  `mobile` cfg guards already cover Android (not just iOS).
- **Launcher icons** — `src-tauri/icons/android/` (all mipmap densities).

## Next steps (need the Android SDK/NDK — run on a machine that has them)

1. **`tauri android init`** → generates `src-tauri/gen/android/` (Gradle
   project) and builds `libpex_lib.so` per ABI via `cargo-ndk`.
2. **Copy these four files** into the generated package
   `app/src/main/java/com/pex/pr_reviewer/`, replacing the stub `MainActivity`.
   Keep the package name (`com.pex.pr_reviewer`, derived from the
   `com.pex.pr-reviewer` identifier with `-` → `_`).
3. **Resolve the `// CHECK:` comments in `WebView.kt`** — prefer reusing wry's
   `RustWebView` (it already wires the `WebViewAssetLoader` @
   `https://tauri.localhost` and the `__TAURI_IPC__` bridge) over the
   hand-rolled `createBareWebView` path.
4. **Manifest/Gradle:** `android:windowSoftInputMode="adjustResize"` on the
   launcher `<activity>`; `minSdk = 24`.
5. **Credentials (blocker):** the `keyring` crate has no Android backend — wire
   the Android Keystore / a Tauri plugin, or guard keyring behind
   `#[cfg(not(target_os = "android"))]` with an encrypted fallback. See the
   AGENTS.md "Android development" section for the caveat.
6. **Run:** `tauri android dev`.
