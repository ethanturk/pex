# Pex Android Frontend — Implementation Plan

> **For Hermes / local agent:** Implement task-by-task. Unlike the iOS plan,
> most of the frontend work is **already done and shared** — the heavy lifting
> here is the native Android shell + toolchain, which needs the Android SDK/NDK
> and therefore must run on a machine that has them (this cannot be completed in
> a sandbox without the Android toolchain).

**Goal:** Add an Android target to Pex using Tauri v2's mobile support, reusing
the existing Rust backend and the already-mobile-adapted Preact/Tailwind
frontend.

**Architecture:** Tauri v2 compiles the Rust backend as a shared library
(`libpex_lib.so`, one per ABI, via `cargo-ndk`) loaded into a native Android
shell (Kotlin). The frontend runs in an Android `WebView`, calling the same
Tauri `invoke()` commands. The Rust code is shared 100%; the frontend is shared
with desktop/iOS (generic `isMobile()` detection already covers Android). Only a
Kotlin shell is platform-specific. Two-tab layout: PRs (review workflow) and
Settings (AI config, accounts, theme), mirroring iOS.

**Tech Stack:** Tauri v2 (mobile), Kotlin + Jetpack Compose (Android shell, API
24+), Preact + TypeScript + Tailwind CSS (shared frontend), Android `WebView`
served via `WebViewAssetLoader` (`https://tauri.localhost`).

**Decisions:**
- Navigation: two-tab bottom nav — PRs + Settings (mirrors iOS `TabView`)
- Layout: adaptive — phone single-column, tablet multi-panel (shared CSS)
- Auth: PAT first (text field, same as desktop/iOS), OAuth deferred
- Network: network-only with SQLite speed cache (no offline mode)
- minSdk: 24 (Android 7.0 — Compose + `WebViewAssetLoader`, ~98% of devices)
- IPC: reuse wry's `RustWebView` + `__TAURI_IPC__` rather than re-rolling

## Implementation Phases

### ✅ Phase 0: Shared frontend & backend (already done)

The mobile-adaptive frontend (`platform.ts`, `MobileShell`, responsive CSS,
touch diff selection, `visualViewport` keyboard avoidance) and the Rust
`mobile` entry point were landed for iOS and are platform-neutral. No Android
work needed here — verify `isMobile()` returns `true` on an Android phone
viewport (it will: touch + `innerWidth < 768`).

### ✅ Phase 1: Kotlin shell templates (this branch)

`src-tauri/android/Pex/` — the four heavily-commented `.kt` templates. Compile
as design docs; need wry symbols filled in (next phase).

### 🔲 Phase 2: Android scaffold

`tauri android init` generates the Gradle project. Verify Rust compiles for the
Android targets and get the blank webview launching in an emulator.

**Steps:**
- Install Android Studio + SDK 34 + NDK; set `ANDROID_HOME` / `NDK_HOME`
- `rustup target add aarch64-linux-android armv7-linux-androideabi i686-linux-android x86_64-linux-android`
- `cd src-tauri && tauri android init` → generates `src-tauri/gen/android/`
- Verify `#[cfg_attr(mobile, tauri::mobile_entry_point)]` is hit on Android
- Confirm a blank webview launches: `tauri android dev`

### 🔲 Phase 3: Navigation shell

Copy the four templates into the generated package
(`app/src/main/java/com/pex/pr_reviewer/`), replacing the stub `MainActivity`.
Wire the real wry WebView.

**Steps:**
- Copy `MainActivity.kt`, `PRsTab.kt`, `SettingsTab.kt`, `WebView.kt`
- In `WebView.kt`, resolve every `// CHECK:` — prefer reusing wry's
  `RustWebView` over the hand-rolled `createBareWebView` path
- Confirm `AndroidManifest.xml` launcher `<activity>` points at `MainActivity`
- Set `android:windowSoftInputMode="adjustResize"` on the `<activity>`
- Set `minSdk = 24` in `app/build.gradle.kts`

### 🔲 Phase 4: Credential storage (BLOCKER — do early)

The `keyring` crate (features `apple-native`, `windows-native`,
`sync-secret-service`) has **no Android backend**. Auth will not work until this
is resolved.

**Options:**
- Add an Android Keystore path (e.g. via a Tauri plugin / `tauri-plugin-stronghold`)
- Or guard keyring calls behind `#[cfg(not(target_os = "android"))]` and use an
  encrypted SQLite/Stronghold fallback for the PAT
- Verify `login_pat` round-trips a token and it survives an app restart

### 🔲 Phase 5: End-to-end smoke test

With the shell + credentials wired, walk the shared frontend on a device:
auth → org select → PR list → diff → comment → AI review. No frontend changes
expected — file issues against shared components only if something is
Android-specific (e.g. WebView quirk).

**Watch for:**
- Soft keyboard covering the comment input (adjustResize + `visualViewport`)
- Predictive back gesture vs. the SPA's internal navigation
- WebView dark-mode (`prefers-color-scheme` + `WebSettingsCompat.setForceDark`)

### 🔲 Phase 6: Polish & Play Store

App icon (already in `src-tauri/icons/android/`), splash, signing config,
`tauri android build` → `.aab`, Play Console metadata + internal testing track.

**Steps:**
- Verify launcher icons render at all densities
- Configure release signing (keystore) in `app/build.gradle.kts`
- `tauri android build` → upload `.aab` to the internal testing track
